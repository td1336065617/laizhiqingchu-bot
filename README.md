# StickerPlugin（表情包管理）

一个面向腾讯 QQ 官方机器人（`qq_official` 适配器）群聊的表情包管理插件。

## 功能

| 指令 | 说明 | 权限 |
| :--- | :--- | :--- |
| `添加{关键词}` | 回复一条包含图片的消息后触发，支持一次回复多张图片批量入库 | 所有人 |
| `来只{关键词}` | 随机发送一张该关键词下的图片 | 所有人 |
| `列表{关键词}{页码}` | 分页查看（每页 10 张，页码可选） | 管理员 |
| `删图{关键词}{序号}` | 按序号删除单张图片 | 管理员 |
| `删除{关键词}` | 二次确认（60 秒内再发一次）后删除整个关键词目录 | 管理员 |
| `统计` | 查看关键词数、图片总数、图片数 Top 3 | 管理员 |
| `菜单` | 查看全部指令与所需权限（群聊需 @机器人） | 所有人 |
| `屏蔽{关键词}` | 屏蔽关键词，禁止再添加 | 管理员 |
| `屏蔽列表` | 查看屏蔽关键词 | 管理员 |
| `解除屏蔽{关键词}` | 解除屏蔽 | 管理员 |

指令采用精确前缀触发：必须以指令名开头才响应，其余消息完全忽略。同时支持
`添加清楚` 与 `添加 清楚` 两种写法（关键词内部不允许包含空格，且不能与指令名重名）。

## 配置

管理员列表与存储上限统一在 **AstrBot 管理面板 → 插件管理 → 表情包管理** 页面中
维护（插件原生配置页仅显示前往该页面的提示，不再提供设置项）。保存后立即生效。

## 存储结构

```
data/stickers/
├── index.json              # {"关键词": ["文件名1.png", ...]}
├── blocked_keywords.json   # 屏蔽关键词列表
├── 关键词A/
│   ├── 1710000000000_1234.png
│   └── ...
└── 关键词B/

data/sticker_backups/        # WebUI 备份产生的压缩包
└── sticker_backup_20260813_150000_1234.zip
```

## WebUI 管理后台

插件提供一个统一的 WebUI 管理页面（AstrBot 管理面板 → 插件管理 → 表情包管理）：

- **管理员设置**：查看/添加/移除管理员 ID（QQ号或 openid），并设置存储上限，保存后立即生效。
- **备份**：点击“立即备份”，把 `data/stickers/` 全部数据（索引、屏蔽列表、所有图片）
  打包为一个 zip 压缩包，包含 `manifest.json` 校验清单（文件数、MD5 清单），列表支持下载。
- **恢复**：上传 zip 后先校验压缩包完整性、`index.json`/`manifest.json` 一致性、
  路径安全性与文件齐全性；校验通过后**合并式恢复**——重叠图片按 MD5 跳过，
  结果会显示归档关键词数/图片数、新增、覆盖、跳过重复、失败数量。

数据目录按 AstrBot 官方规范优先解析 `get_astrbot_data_path()`，最终为
`<AstrBot数据目录>/stickers`（即通常的 `data/stickers/`）。

## 实现说明与注意事项

- 图片保存统一使用组件自带的 `convert_to_file_path()` 落地为本地文件，
  不依赖未公开的 `context.download_file` 接口。
- 发送图文消息使用 `event.chain_result([Plain(...), Image.fromFileSystem(...)])`；
  `Image.from_file()` 不是 AstrBot 的 API。
- 引用消息通过消息链中的 `Reply` 组件读取，遍历 `reply.chain` 提取 `Image`。
  QQ 官方适配器是否填充引用消息的完整内容（含图片）取决于 AstrBot 版本与
  适配器实现，请在实际部署中验证“添加”功能；若被引用图片无法获取，
  插件会按设计完全忽略该消息。
- 批量删除会把整个关键词目录移除，且不可恢复，请谨慎使用。
- 关键词会过滤空白字符、指令名、路径分隔符等非法字符，防止路径穿越。

## 部署

将本目录（`metadata.yaml`、`main.py`、`_conf_schema.json`、`pages/`）放入
`AstrBot/data/plugins/sticker_plugin/`，然后在 WebUI 插件管理页启用并重载插件。
