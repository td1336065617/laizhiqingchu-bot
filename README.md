# StickerPlugin（表情包管理）

一个面向腾讯 QQ 官方机器人（`qq_official` 适配器）群聊的表情包管理插件。

## 功能

| 指令 | 说明 | 权限 |
| :--- | :--- | :--- |
| `添加{关键词}` | 回复包含图片的消息批量入库 | 所有人 |
| `批量添加合并转发{关键词}` | 先发送命令，90 秒内本人发送的合并转发自动批量入库 | 所有人 |
| `来只{关键词}` | 随机发送一张该关键词下的图片 | 所有人 |
| `列表{关键词}{页码}` | 分页查看（每页 10 张，页码可选） | 管理员 |
| `删图` | 回复要删除的图片，按 MD5 自动定位并删除（也可 `删图{关键词}` 限定关键词，或 `删图{关键词}{序号}` 按序号删除） | 管理员 |
| `删除{关键词}` | 二次确认（60 秒内再发一次）后删除整个关键词目录 | 管理员 |
| `统计` | 查看关键词数、图片总数、图片数 Top 3 | 管理员 |
| `表情包管理菜单` | 查看全部指令与所需权限（优先转为图片） | 所有人 |
| `屏蔽{关键词}` | 屏蔽关键词（禁止添加、发送、查看），`解除屏蔽{关键词}` 恢复 | 管理员 |
| `屏蔽列表` | 查看屏蔽关键词 | 管理员 |
| `解除屏蔽{关键词}` | 解除屏蔽 | 管理员 |

指令采用精确前缀触发：必须以指令名开头才响应，其余消息完全忽略。同时支持
`添加清楚` 与 `添加 清楚` 两种写法（关键词内部不允许包含空格，且不能与指令名重名）。
所有指令也兼容 QQ 官方指令面板自动添加的 `/` 前缀，例如 `/来只清楚`。
`表情包管理菜单` 保留原版文字排版，正常情况下会先生成 HTML 并转换为 PNG；
运行环境没有可用浏览器时使用 Pillow，所有渲染器不可用才回退为原版文字。
菜单图片默认使用 `Noto Sans CJK SC` 的简体中文字体面；如需指定字体文件，
可设置 `STICKER_MENU_FONT`，使用 TTC 字体时可通过 `STICKER_MENU_FONT_INDEX`
指定字体面索引。Emoji 使用插件自带的
`assets/fonts/NotoColorEmoji.ttf`，不依赖服务器安装字体；Pillow 会先高分辨率
绘制再缩放，字体加载失败时使用安全符号兜底。可通过
`STICKER_MENU_EMOJI_FONT` 和 `STICKER_MENU_EMOJI_FONT_INDEX` 覆盖字体路径与字体面。

## 配置

管理员列表与存储上限统一在 **AstrBot 管理面板 → 插件管理 → 表情包管理** 页面中
维护（插件不提供 AstrBot 原生配置表单，与内置插件一致）。保存后立即生效。

## 存储结构

```
data/stickers/
├── index.json              # {"关键词": ["文件名1.png", ...]}
├── blocked_keywords.json   # 屏蔽关键词列表
├── 关键词A/
│   ├── 1710000000000_1234.png
│   └── ...
└── 关键词B/

data/sticker_backups/        # WebUI 备份产生的压缩包
└── sticker_backup_20260813_150000_1234.zip
```

## WebUI 管理后台

插件提供一个统一的 WebUI 管理页面（AstrBot 管理面板 → 插件管理 → 表情包管理）：

- **管理员设置**：查看/添加/移除管理员 ID（QQ号或 openid），并设置存储上限，保存后立即生效。
- **备份**：点击“立即备份”，把 `data/stickers/` 全部数据（索引、屏蔽列表、所有图片）
  打包为一个 zip 压缩包，包含 `manifest.json` 校验清单（文件数、MD5 清单）；
  列表支持下载与删除（删除为二次确认，仅删除压缩包，不影响现有表情包数据）。
- **恢复**：上传 zip 后先校验压缩包完整性、`index.json`/`manifest.json` 一致性、
  路径安全性与文件齐全性；校验通过后**合并式恢复**——重叠图片按 MD5 跳过，
  结果会显示归档关键词数/图片数、新增、覆盖、跳过重复、失败数量。
- **清空**：二次确认后删除全部关键词与图片（不可恢复，建议先备份）；
  不影响管理员设置与屏蔽列表。

## 备份格式与迁移

备份/恢复**不依赖任何第三方 SDK 或云服务**：打包与解压使用 Python 标准库
`zipfile`，WebUI 页面的上传/下载走 AstrBot 自带的插件页面桥接接口，安装后
开箱即用。备份文件是标准 zip，内含 `index.json`、`blocked_keywords.json`、
全部图片和 `manifest.json` 校验清单，可直接复制到其他机器；在另一台 AstrBot
部署本插件后，打开“表情包管理”页上传该 zip 即可合并导入（重叠图片按 MD5 跳过）。

数据目录按 AstrBot 官方规范优先解析 `get_astrbot_data_path()`，最终为
`<AstrBot数据目录>/stickers`（即通常的 `data/stickers/`）。

## 实现说明与注意事项

- 图片保存统一使用组件自带的 `convert_to_file_path()` 落地为本地文件，
  不依赖未公开的 `context.download_file` 接口。
- 发送图文消息使用 `event.chain_result([Plain(...), Image.fromFileSystem(...)])`；
  `Image.from_file()` 不是 AstrBot 的 API。
- 引用消息通过消息链中的 `Reply` 组件读取，遍历 `reply.chain` 提取 `Image`。
  QQ 官方适配器是否填充引用消息的完整内容（含图片）取决于 AstrBot 版本与
  适配器实现，请在实际部署中验证“添加”功能；若被引用图片无法获取，
  插件会按设计完全忽略该消息。
- **合并转发批量添加**：QQ 官方平台对合并转发（`message_type=102`）实际推送
  的是渲染后的文字摘要（`msg_elements` 为空），图片 URL 内嵌在摘要的
  `[附件N] 类型:图片 文件名:... URL:...` 文本行中。使用专用命令
  `批量添加合并转发{关键词}`：发送命令后机器人进入 90 秒等待状态，随后
  **命令发送者本人**发送合并转发，机器人自动从摘要中提取全部图片 URL 批量入库
  （同时兼容带顶层附件、嵌套元素、JSON 内容的推送结构）；其他人发送的转发不会被误用。
- 批量删除会把整个关键词目录移除，且不可恢复，请谨慎使用。
- 关键词会过滤空白字符、指令名、路径分隔符等非法字符，防止路径穿越。

## 部署

将本目录（`metadata.yaml`、`main.py`、`pages/`）放入
`AstrBot/data/plugins/sticker_plugin/`，然后在 WebUI 插件管理页启用并重载插件。

## 更新

1. 拉取最新代码（`git pull`），查看 [CHANGELOG.md](CHANGELOG.md) 了解本次改动；
2. 把 `main.py`、`metadata.yaml`、`pages/` 同步到服务器/本机的
   `AstrBot/data/plugins/sticker_plugin/`；
3. 在 AstrBot WebUI 插件管理页重载插件（或重启 AstrBot）。

`data/stickers/` 与 `data/config/` 下的数据不会被覆盖，更新不会丢失表情包。
